# Qwen3.5-0.8B 单 Ascend 910C chip 实施计划

## 1. 目标与范围

在单个 Ascend 910C chip 上，通过 TokenSpeed 完成 Qwen3.5-0.8B 权重加载、Prefill、连续 Decode、分层正确性验证和可比较的性能基线。主要模型计算必须在 NPU 上执行，不能通过跳过层、近似状态更新或 CPU 执行主要计算达成验收。

本计划以文本输入和完整文本生成路径作为首个交付范围；确认课程是否另外要求视觉输入，并在报告中明确范围。首轮采用 batch size 1、非量化权重、贪心解码；BF16 作为候选计算精度，状态和累加精度遵循参考实现并单独记录。设备拓扑中的 chip 与逻辑设备编号须实测确认，不能仅凭设备可见数判定。

以尽快完成可验收交付为目标，按依赖与验收门槛连续推进，不设按天等待节点。前置条件满足后立即开展下一项；测试随适配同步补齐。以下任务均为待执行，不能视为已通过测试。

## 3. 工作包与验收门槛

### P0：环境、权重及设备确认

1. 确认现有虚拟环境并激活；记录 nanoGPT 启动命令与可用状态，隔离新增依赖。
2. 记录主机架构、驱动、固件、CANN、Python、框架和扩展版本，以及 NPU 物理拓扑、逻辑编号和 HBM 容量。
3. 核实单 chip 映射，显式限制可见设备，所有并行规模设为 1；通过进程和设备监控验证实际使用范围。
4. 固定模型来源、revision、配置、tokenizer 和权重文件清单；核实模型类、层类型、头数、维度、卷积宽度及权重映射。
5. 审阅安装脚本后再决定环境变更。先验证基础张量运算和仓库 NPU 算子，再用已有 Qwen3-0.6B 配方隔离环境问题；辅助模型不可获取时记录原因，继续基础算子检查。

**验收：**依赖可导入，基础 NPU 计算通过；单 chip 映射明确；目标权重可读取。输出 `docs/setup.md`，仅登记实际验证的命令和结果。

### P1：计算路径与缺口清单

建立 `docs/ascend-qwen35-operator-matrix.md`，逐项记录功能、主要输入输出形状、dtype、布局、实现来源、平台注册、硬件测试状态和测试方法。支持状态统一区分：已有实现／可分派／实测通过／阻塞。

至少覆盖：Embedding、线性投影与 MLP、RMSNorm 与门控归一化、RoPE、Attention、KV 写入、GDN 门控与递推、因果卷积、LM head 和采样。

重点追踪：`Qwen3_5GatedDeltaNet` → 状态后端 → 卷积与 GDN 算子分派 → NPU kernel → 状态提交。记录各步输入输出、布局变换、临时分配和同步点。

GDN 公共状态契约为 `[N, H, V, K]`，已查看的 Triton Prefill 内部使用 `[N, H, K, V]`；适配时显式核对转换及写回。卷积状态契约在源码中为 `[num_slots, R, D]`，必须确认历史窗口语义、初始化和槽位回收。

**验收：**每个关键模块有对应实现或明确缺口；首个阻塞点可用最小输入复现。不得仅扩大平台注册范围就宣布支持 NPU。

### P2：补齐模块并打通完整推理

按依赖推进：权重加载 → 模块独立对照 → 完整 Prefill → 单步 Decode → 多步 Decode → 连续请求。

- 优先复用已验证 NPU 算子；缺失模块可先用正确的 NPU 张量算子组合实现，再考虑融合。
- 保留完整模型数学语义；记录每项复用、包装、修改和新增实现。
- 核对参数缺失、重复、形状和布局转换；对允许不加载的参数明确说明原因。
- 首轮禁用量化、投机解码等额外特性，缩小定位范围。按已有 NPU 配方显式处理 PDL 与 Prefill 图限制。
- 若 GDN 阻塞 ACL Graph，可先在统一执行路径中使用已有 eager 配置定位；必须记录该选择，之后将图捕获作为独立验证项，不能套用其他模型的成功结论。
- 每个请求正确初始化、更新、释放 KV、卷积和递推状态；检查槽位复用与前缀缓存行为。首轮可显式关闭前缀复用，报告须注明范围。

**验收：**单 chip 上短输入可连续生成至少 32 Token（正确处理提前 EOS），日志无未解释的权重缺失、NaN/Inf 或 CPU 主计算回退；多个独立请求可连续运行。

### P3：分层正确性验证（随开发执行）

固定权重、tokenizer、输入 Token、精度、随机种子、生成配置与参考实现版本。

| 层级 | 覆盖与判据 |
| --- | --- |
| 算子 | 真实模型形状、长度 1、卷积窗口及分块边界前后、非整齐长度；对比可信参考输出 |
| 有状态模块 | 零／非零初始状态、多步递推、整段与等价分段处理；逐步比较输出和内部状态 |
| 生命周期 | B 单独执行与 A 完成后重新初始化再执行 B 对照；请求交错、槽位复用，不得串扰 |
| 模型 | 多种输入长度，固定上下文逐步对比 logits，并检查自由生成；差异时定位首个分歧层／步 |
| 执行模式 | 若启用 ACL Graph 或前缀缓存，分别与已通过的基础配置对照 |

先使用小形状高精度参考检查数学语义，再比较目标精度。记录最大绝对误差、稳定化相对误差及误差分布；按 dtype、参考舍入误差和递推长度预先确定 atol/rtol，禁止为迁就错误事后随意放宽。Token 一致率仅作辅助，近似并列 logits 的分歧需解释。

测试应验证真实行为。复用现有测试框架，在 `test/runtime/` 和 `tokenspeed-kernel-npu/test/` 的合适位置补充案例；缺少 NPU 导致的跳过必须单列，不能计为通过。

**验收：**关键模块和端到端测试可重复执行，数值阈值有依据，状态隔离和多步更新通过。保存配置、结果与失败定位记录。

### P4：性能基线与瓶颈

仅对 P3 通过的配置测量，batch size 固定为 1。计划测试以下四组，长度以实际 Token 计数：

| 输入 Token | 目标生成 Token |
| ---: | ---: |
| 128 | 32 |
| 128 | 128 |
| 2048 | 32 |
| 2048 | 128 |

若 EOS 提前终止，记录实际长度；固定长度基准须使用实现已支持的配置，并与正常 EOS 正确性测试分开。长度调整必须记录原因。

- 每组至少 3 次预热、10 次正式测量，报告中位数及离散程度；编译、加载和图捕获开销另列。
- 区分服务端 Prefill 时间、用户可见 TTFT 和 Decode TPOT；TTFT 说明是否包含分词、排队及网络。TPOT 使用首 Token 后耗时除以实际生成数减一。
- 设备计时在边界做必要同步；服务端测量只执行单请求，避免排队混入计算基线。
- HBM 分别记录加载后占用、缓存预分配量及推理峰值，注明指标来自分配器还是设备监控。
- 使用 profiler 或分模块计时，区分 kernel 计算、访存、布局转换、设备传输和主机调度；不能仅凭总耗时断言瓶颈。
- 如有余量，仅优化一个有测量证据的瓶颈；同配置复测性能并重跑相关正确性测试。

**验收：**四组结果及可复现配置齐全，至少一个主要开销有测量证据。输出小型 CSV/JSON 到 `results/`；大型 trace 和权重保存在仓库外。

### P5：复测、报告与提交

从干净进程按文档重跑启动、关键测试、端到端验证和基线。报告开头写明成员贡献，随后说明环境、计算路径、适配清单、关键模块调用链、正确性证据、性能及局限。

公开 PR 的描述与附件仅包含可公开的技术信息。创建代码提交前按仓库要求执行 `pre-commit run --all-files` 并 sign off。本计划本身不执行安装、提交、推送或教学网提交。

## 4. 依赖、分工与风险处理

关键路径：P0 → P1 → GDN／卷积缺口修复 → 完整推理 → P3 → P4 → 报告。优先复用已有实现，以正确的 NPU 组合算子快速补齐缺口；报告和复现记录随执行更新，避免最后集中补写。独立的环境盘点、源码梳理和测试准备可由组员同时推进；性能测量必须等待对应配置通过正确性验证。可由组员分别负责环境与集成、关键模块、验证与性能；发现阻塞立即汇总证据并调整任务顺序。此分工是小组建议，不代表已分派执行。

| 风险 | 处理与停止条件 |
| --- | --- |
| 当前机器没有目标 NPU 或权重 | 继续源码梳理、参考实现和测试准备；硬件正确性与性能保持待验证 |
| 依赖变化破坏 nanoGPT | 隔离环境，保存版本与启动记录，禁止无记录全局升级 |
| GDN／卷积不能在 Ascend 编译 | 优先正确的 NPU 组合实现；保留算子接口和状态契约 |
| 单步正确但长序列漂移 | 比较每步状态、布局、精度与缓存索引，定位首个分歧 |
| 图捕获或服务框架阻塞 | 先验证模块与已有 eager 执行路径，再补服务集成；明确性能模式 |
| 可选工作拖慢交付 | 将融合优化、额外功能及非必需执行模式后置，优先完成完整计算、分层正确性及四组基线 |
